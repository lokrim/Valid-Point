# Decisions, defaults and explicit gates

## Decisions fixed by the current brief

New independent Python project; planning-only setup; no detector dependency;
synthetic first; two tracks with required GT-free inference; no manually fixed
factor weights; strict unknowns; peer consensus diagnostic first; next-frame
quotas; exact-byte accounting; at least four labeled comparison segments beyond
development; visible notebooks and report-ready provenance at every implemented
stage; failed hypotheses are legitimate findings.

## Genuine researcher decisions

Only these need input before dependent future work; they do not block this setup:

1. Confirm the proposed false-alarm target (1%) and whether honest-view loss has
   a practical maximum or should initially be reported as a Pareto trade-off.
   Until a limit is chosen, do not claim an allocation is operationally acceptable.
2. Confirm acquisition/storage resources for four comparison archives plus the
   untouched final archive and optional development archive, processed one at a
   time. Their public listing does not authorize downloading during setup.
   Freeze actual segment roles after metadata preflight, before outcomes.
3. Confirm whether trusted quota enforcement is a plausible intended deployment
   assumption. Otherwise restrict primary claims to receiver processing/admission
   savings and treat link-enforced savings as a simulation scenario.

The researcher reviews this proposal before invoking S00. No stage prompt
automatically invokes another. Changes after result exposure remain visible
and cannot erase the earlier outcome or restore holdout status.

## Gates and failure behavior

| Gate | Required visible evidence | If not met |
| --- | --- | --- |
| G0 — planning review | Scaffold verification and requirement coverage, researcher review | Stop here; no scientific implementation |
| G1 — contracts | S00/S01 fresh-kernel notebooks, causal units/unknown/seed tests | Correct contracts before factors |
| G2 — factors and score | S02/S03 raw displays, fit/calibration lineage, hand cases, monotonicity/unknown tests | No detection claims; record sparse/degenerate references |
| G3 — GT-free viability | S04 GT-isolation and oracle-gap/failure evidence | Record negative result, block operational/real policy claim; oracle study may remain descriptive |
| G4 — peer eligibility | S05 independent quorum/comparability and collusion/conflict evidence | Keep consensus unknown/diagnostic; K/S may proceed |
| G5 — causal byte policy | S06 next-frame ledger, enforcement scope, actual-byte fairness and censored-observation tests | No transmission-saving or utility claim |
| G6 — overlays | S07 production-reader round trips, original immutability, full attempt ledger | No attack evaluation from invalid overlays |
| G7 — synthetic evaluation | S08 complete preregistered grid, failures, coverage and paired uncertainty | Repair validation, or record a negative scientific outcome |
| G8 — real intake | S09 archive/time/label/transform preflight, four valid labeled comparison segments and frozen split | Real comparison incomplete; synthetic-only reporting allowed |
| G9 — held-out comparisons | Per-segment/aggregate evidence, no leakage, GT-free policies, exposed-holdout log | No completed real-data policy claim; show failed/blocked cells |
| G10 — paper readiness | S10 claim-to-evidence mapping, reproducibility, negative results and limitations | Remove unsupported claims; no invented values |
| GT — temporal extension | Causal state machine, initialization/reset, thresholds, separate calibration and fresh notebook | No temporal alarm detection/recovery claim |
| GL — learned combiner | Training-only grouped fitting, monotonicity, separate calibration, fair baseline comparison | Retain weight-free baseline; no universal optimal weights |
| GD — detector/fusion | Independent model/checkpoint/license/runtime/input gate, genuine predictions and AP evaluation notebook | No AP@0.5/0.7, detector utility, ROBOSAC/MADE or fusion claims |
| GP/GX — probability/transfer | Defined binary target and calibrated probability / independently validated second dataset | No ECE/reliability of T or cross-dataset claims |

A gate can be “technically passed; hypothesis unsupported.” Preserve that
distinction in every record. Scientific weakness does not justify dropping a
case, changing thresholds on test data or hiding an unknown state.
